{% comment %} The whole in-flight turn: the evaluator's critique of the prompt, the streaming answer, and the evaluator's critique of that answer. All three share one SSE connection, so their order on screen is fixed by the markup rather than by which of the three models happens to finish first. `token` events are NOT swapped by htmx. hx-swap="none" leaves the data alone and app.js cancels the swap outright, accumulates the raw markdown, and re-renders it into .stream-markdown on each animation frame -- so headings, lists and code blocks format as they arrive instead of appearing as literal syntax until the end. Two reasons it is not left to htmx: a swap inserts the data as HTML, and this data is model output; and appending text can only ever append text, never re-format what came before it. The final `done` event replaces the bubble with the server-rendered HTML. That is the copy that gets stored and re-served on reload, so the client-side render only ever has to be a good preview -- the server has the last word, and any difference between the two parsers resolves at that swap. It is also the event named in sse-close, so nothing may be sent after it. {% endcomment %}
